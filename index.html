Transformers, Multi-Head Attention & BERT

From neural networks to Transformers

A feed-forward layer computes a = f(Wx + b). It has no notion of order or context, so "bank" in "the bank approved the loan" and "the river bank" gets the same vector. RNNs add a hidden state, h_t = tanh(W_x x_t + W_h h_(t-1) + b), but they process tokens one at a time (no parallelism), suffer vanishing gradients, and compress the past into one vector. LSTM/GRU add gates (forget, input, output; update, reset) which help, yet remain sequential.

The Transformer (Vaswani et al., 2017, Attention Is All You Need) drops recurrence: every token attends to every other token directly, so training is parallel across the sequence and any two tokens are connected by a path of length one.

Self-attention: Q, K, V and the maths

Each token vector x is projected into a query (what I am looking for), key (what I offer for matching) and value (what I contribute when matched): Q = XW_Q, K = XW_K, V = XW_V.

Attention(Q, K, V) = softmax( Q K^T / sqrt(d_k) + M ) V
M = 0 where allowed, -inf where masked (causal: j > i)

Dividing by √d_k keeps logit variance near 1: if q and k entries have unit variance, q·k has variance d_k, so unscaled logits grow with dimension and push softmax into saturation where gradients vanish.

Logits are illustrative, designed so "it" prefers "file". Lower the temperature to sharpen, raise it to flatten. Turn on the causal mask to see GPT-style behaviour: each row only sees tokens at or before its own position. Pick a row to inspect one token.

Multi-head attention, FFN and normalisation

Run h attention heads in parallel, each in a d_k = d_model / h subspace, concatenate and project: MHA = Concat(head_1..head_h) W_O. BERT-base: d=768, h=12, d_k=64. Heads are not guaranteed to be interpretable, but different heads empirically specialise (syntax, coreference, positional offsets).

The FFN is applied per token: FFN(x) = W2 σ(W1 x), 768→3072→768 in BERT; modern models use SwiGLU. Around each sub-layer sit a residual connection and normalisation: post-LN (original) LN(x + F(x)) versus pre-LN (modern) x + F(LN(x)), which trains more stably at depth. Most LLMs use RMSNorm.

Positional information

Attention is permutation-equivariant, so order must be injected. Original: sinusoidal PE(pos,2i)=sin(pos/10000^(2i/d)). BERT: learned absolute embeddings. Modern LLMs: RoPE rotates q and k by position-dependent angles so that q_m·k_n depends on m−n; ALiBi adds a distance-proportional bias to logits. Context-extension tricks (position interpolation, NTK scaling, YaRN) rescale RoPE frequencies.

BERT

Encoder-only, bidirectional. Input = token + segment + position embeddings; [CLS] at the start and [SEP] between segments. Pretraining: MLM (mask 15% of tokens; of those 80% [MASK], 10% random, 10% unchanged) and NSP (later shown unnecessary by RoBERTa). Fine-tune by adding a task head on h_CLS (classification), per-token heads (NER), or span heads (QA).

Efficiency developments

FlashAttention

Exact attention computed in SRAM tiles with online softmax; avoids materialising the N×N matrix in HBM. Same maths, far less memory traffic.

MQA / GQA

Share K/V heads across query heads to shrink the KV cache (MQA: 1 KV head, GQA: g groups).

MLA

DeepSeek's Multi-head Latent Attention caches a low-rank latent and re-expands to K/V, cutting cache further.

MoE

A router sends each token to top-k of many expert FFNs: huge capacity, fewer active parameters per token.

SSM / hybrids

Mamba-style selective state spaces give linear-time sequence mixing; hybrids interleave a few attention layers.

Sparse / local attention

Sliding window, local-global (ModernBERT), chunked attention reduce O(N²) for long context.

Code: multi-head attention in PyTorch

import torch, torch.nn as nn, torch.nn.functional as F

class MHA(nn.Module):
    def __init__(self, d_model=768, heads=12, causal=False):
        super().__init__()
        assert d_model % heads == 0
        self.h, self.dk, self.causal = heads, d_model // heads, causal
        self.qkv = nn.Linear(d_model, 3 * d_model)
        self.out = nn.Linear(d_model, d_model)

    def forward(self, x, attn_mask=None):          # x: (B, T, D)
        B, T, D = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q, k, v = (t.view(B, T, self.h, self.dk).transpose(1, 2) for t in (q, k, v))
        y = F.scaled_dot_product_attention(        # fused / FlashAttention kernel
            q, k, v, attn_mask=attn_mask, is_causal=self.causal and attn_mask is None)
        return self.out(y.transpose(1, 2).reshape(B, T, D))

print(MHA()(torch.randn(2, 10, 768)).shape)        # torch.Size([2, 10, 768])

Large Language Models

Training, adaptation and inference

Pretraining minimises next-token cross-entropy over trillions of tokens. SFT teaches the instruction format on curated demonstrations. Preference optimisation (RLHF with PPO, DPO, or GRPO-style RL with verifiable rewards) shifts behaviour toward helpfulness, safety and reasoning. Compute-optimal scaling (Chinchilla) suggests ~20 training tokens per parameter, but modern small models are deliberately over-trained for cheaper inference.

Decoding and sampling

Greedy picks argmax. Temperature T rescales logits softmax(z/T). Top-k keeps the k best tokens; top-p keeps the smallest set whose cumulative probability ≥ p; min-p filters relative to the top probability. Speculative decoding uses a small draft model to propose tokens that the large model verifies in one pass.

Sampling labtemperature · top-k · top-p
Next-token distribution for "The capital of France is ___" from fixed illustrative logits. Watch the kept set shrink as you tighten top-k / top-p, and the distribution flatten as temperature rises.

Serving at scale

Two phases: prefill (process the prompt in parallel, compute-bound) and decode (one token at a time, memory-bandwidth-bound because weights and KV cache are re-read each step). Key techniques: KV cache, continuous batching, PagedAttention (vLLM), prefix caching, quantisation (INT8/FP8/INT4, GPTQ, AWQ), tensor/pipeline parallelism, speculative decoding. Metrics: time-to-first-token, inter-token latency, throughput, cost per million tokens.

Retrieval-Augmented Generation (RAG)

RAG grounds an LLM in external knowledge: retrieve relevant passages at query time and place them in the prompt. It gives fresh data, private data, citations and a smaller hallucination surface, without retraining.

# Reciprocal Rank Fusion: score(d) = sum over rankers of 1 / (k + rank_r(d)),  k ~ 60
def rrf(rankings, k=60):
    s = {}
    for ranking in rankings:
        for r, doc in enumerate(ranking, 1):
            s[doc] = s.get(doc, 0) + 1 / (k + r)
    return sorted(s, key=s.get, reverse=True)

Agentic AI

Anthropic's useful distinction: workflows orchestrate LLMs and tools through predefined code paths; agents let the LLM dynamically direct its own process and tool use. Both are "agentic systems". Start with the simplest thing that works and add autonomy only when it measurably helps.

The loop ends on a stop condition, a step/budget limit, an error escalation, or a human decision. Dashed edges are governance paths.

Workflow and agent patterns

Prompt chaining

Fixed sequence of calls with gates. Trade latency for accuracy.

Routing

Classify then dispatch to a specialised prompt, tool or smaller model.

Parallelisation

Sectioning (independent subtasks) or voting (diverse samples).

Orchestrator-workers

Lead model decomposes dynamically, workers execute, lead synthesises.

Evaluator-optimiser

Generator and critic iterate against clear criteria.

Autonomous agent

Open-ended loop with tools, environment feedback and checkpoints.

Interactive: MCP and agent-to-agent protocols

MCP (Model Context Protocol) is an open standard, "USB-C for AI": a host application runs MCP clients that connect to MCP servers exposing tools (actions), resources (data) and prompts (templates) over stdio or streamable HTTP. A2A addresses agent-to-agent collaboration and discovery (agent cards, tasks). MCP is vertical (agent to tools); A2A is horizontal (agent to agent).

Protocol mapMCP vs A2A
Security points: tool-description injection, over-broad scopes, confused deputy, token passthrough. Always authenticate, scope least privilege, and require consent for side-effecting tools.

Agentic AI: interview Q&A

Harness Engineering

The harness is everything around the model that turns a next-token predictor into a working agent: the loop, system prompt, tools and their schemas, context management, permissions and sandboxing, hooks, memory, orchestration of sub-agents, tracing and evaluation. The model supplies reasoning; the harness supplies reliability. Two teams using the same model can get very different results purely from harness quality, which is why it is a rising interview topic.

Long-running agents: the initializer / worker pattern

Anthropic's write-up on long-running agents describes sessions as shifts with no memory of the previous shift. Their fix, in harness terms:

  1. Initializer session creates an init.sh, a progress log and a first git commit, and expands the request into a JSON feature list with every item initially failing.
  2. Each worker session reads the progress file and git log, starts the dev server, runs a basic end-to-end check, picks one failing feature, implements it, tests it like a user (browser automation), commits, and updates the log.
  3. Workers may flip only the passes field; deleting or editing tests is forbidden. JSON is used because models alter it less carelessly than Markdown.

This counters two classic failure modes: trying to one-shot everything, and declaring victory early.

Harness Engineering: interview Q&A

Context Engineering

Prompt engineering is writing good instructions. Context engineering is curating everything that enters the window on every call: system prompt, tool definitions, retrieved documents, memory, message history and tool results. The goal is the smallest set of high-signal tokens that makes the desired behaviour likely. Context is a finite resource with diminishing returns: as it grows, recall degrades ("context rot"), and attention cost grows quadratically.
